# Bundled SRD Core Pack

This directory owns Tavern Born's generated SRD 5.1 + SRD 5.2.1 resource pack.

- `provenance.json` pins the official documents, hashes, prescribed attribution, license, and
  transformation notice.
- `dependency-allowlist.json` records every audited exception: excluded roots, stripped references
  to non-SRD material, and untagged support rows required by SRD roots. Each rule includes its audit
  reason; support rows also name the owning SRD and official section. Generation fails when an
  approval is missing, duplicated, or no longer used. Its `allowedSources` list is also the
  fail-closed boundary for source-qualified data that survives metadata stripping.
- `THIRD_PARTY_NOTICES.md` contains the two prescribed attributions, official source links,
  license, pack version, and Tavern Born transformation notice that ship beside approved data.
- `data/` and `manifest.json` are generated by `scripts/build-srd-snapshot.mjs`. They are not
  committed or packaged while provenance status is `provenance-review-required`.

Generate a non-distributable review snapshot and CSV checklist from an explicit external
5etools-format checkout:

```text
npm run review:srd -- --source-root data --upstream-revision <pinned-revision>
```

Review output is written to the ignored `.tmp/srd-review/` directory. The CSV has one row per
transformed record with blank review-status, official-location, and notes columns. While provenance remains
`provenance-review-required`, the generator refuses to write beneath `resources/srd/core`.
Follow the complete [human provenance review checklist](../../../docs/srd-provenance-review.md);
review approval is bound to each transformed record hash and must be repeated when that hash
changes.

Verify that a checked snapshot matches the same input:

```text
npm run verify:srd -- --source-root data --output-root <reviewed-snapshot> --upstream-revision <pinned-revision>
```

The generator reads the source root but never writes to it. It also closes structural class,
subclass, inline subclass-feature, base-item, and source-qualified equipment references before
output is accepted. Unmarked equipment groups are admitted only through explicit dependency
approvals, and their concrete item links must also resolve. It strips known publication, catalog,
supplemental, and presentation metadata; rejects image payloads and unexpected source-qualified
fields; and reports stripped-field counts in the manifest. Mechanical structures such as
`_versions` remain intact. The manifest also inventories every distributed row with its file,
collection, source-qualified identity, SRD marker/version or dependency approval, and a hash of the
transformed record. Ambiguous markers, unexplained rows, cross-file identity collisions, and
missing approved dependencies fail generation. Verification reports missing, stale, and
unexpected managed files together.

Release packaging includes only `data/`, `manifest.json`, and `THIRD_PARTY_NOTICES.md` from this
directory. The distribution command fails unless both provenance and manifest are marked
`approved-for-distribution`, their legal metadata and pack versions agree, notices are current,
the data-file set exactly matches the manifest, and every packaged JSON checksum verifies.
